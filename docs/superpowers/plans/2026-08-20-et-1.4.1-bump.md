# ExecuTorch v1.4.1 Pin Bump Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut release `v1.4.1-1` of executorch-runtime-dist — the full matrix built against ExecuTorch `v1.4.1` — with the vendored XNNPACK workspace-size patch regenerated so the `workspace_size_bytes` consumer contract survives the move.

**Architecture:** Two content commits on `chore/et-1.4.1`. The first regenerates `patches/et-xnnpack-workspace-size.patch` and refreshes `test/fixtures/etpatch/` from pristine v1.4.1 sources — in lockstep, because the hermetic patch test reads the fixtures and would otherwise pass against a stale copy of itself. The second moves every hardcoded `1.3.1` / `2.12.0+cpu` string. Then PR → `full` gate → a manual Windows build on `winbox` → merge → tag.

**Tech Stack:** Bash under `set -euo pipefail`, `git apply`, CMake + Ninja, GitHub Actions, `gh` CLI, `uv` (for requirements locks).

**Spec:** `docs/superpowers/specs/2026-08-20-et-1.4.1-bump-design.md`

## Global Constraints

- **ET pin:** `v1.4.1`, commit `e4d02f41f7909e8ed5bf4a14ffc520d733453d9f`. Previous pin was `v1.3.1` / `e2f18eb23c45bd22ca332b0b8b49a81de304b472`.
- **Torch pin:** `torch==2.13.0+cpu`. Previous was `torch==2.12.0+cpu`. Confirmed present on `download.pytorch.org/whl/cpu` for `cp312` on `manylinux_2_28_x86_64`, `manylinux_2_28_aarch64`, `win_amd64`.
- **Release tag to cut:** `v1.4.1-1`.
- **Out of scope, do not touch:** `scripts/lib/openvino.sh` and the OpenVINO bundle (`2025.4.1`); `.build-image`; the install-destination `sed` at `build-runtime.sh:182-198`; `docs/handover-to-engine.md`; `docs/handover-windows-static-cxx17.md`; anything under `docs/superpowers/{specs,plans}/` other than files this plan creates; `spike/`; `2026-07-02-executorch-runtime-dist-design.md`.
- **Test literals stay:** `v1.3.1-2` in `test/classify_gate.test.sh` and `1.3.1` in `test/discover_pin_rows.test.sh` are arbitrary fixture values exercising tag parsing and filename discovery, not pins. Do not rewrite them.
- **XNNPACK submodule pin is unchanged** across the two ET tags (`1adaa7c709d4839d29e1f219cb962b01c9e6a905`). `patches/xnnpack-workspace-size-accessor.patch`, `test/fixtures/etpatch/xnnpack.h` and `test/fixtures/etpatch/runtime.c` must **not** change.
- **Shell convention:** `grep` exits 1 on no-match, which aborts under `set -e`/`pipefail`. Guard with `|| true`, matching existing code.
- **Branch:** all work lands on `chore/et-1.4.1` (already created, already holds the spec commit).

The only engineering in this release. `patches/et-xnnpack-workspace-size.patch` fails to apply to v1.4.1 because upstream inserted new weight-cache options into the exact anchor windows our hunks target. This is context drift, not semantic conflict: upstream still has no workspace-size accessor.

**Method note (refines the spec).** The spec called for a `git worktree` at v1.4.1. That is unnecessary and slower: `git show v1.4.1:<path>` yields the same pristine bytes without checking out a multi-GB tree, and the five files involved *are* the fixture set. So refresh the fixtures first, then build the synthetic tree **out of the refreshed fixtures**, edit, and `git diff` the patch back out. Lockstep then holds by construction rather than by discipline. The one rule from the spec that still binds absolutely: never generate from `/home/corey/workspace/executorch`, whose working tree is already dirty with our own applied patches.

**6b — `get_option`.** Upstream's chain now ends with the `packed_cache_path` branch. Append ours
after it, so the function ends:

```cpp
  } else if (strcmp(option.key, packed_cache_path_option_key) == 0) {
    std::array<char, runtime::kMaxOptionValueLength> arr{};
    const std::lock_guard<std::mutex> lock(path_mutex_);
    size_t len =
        std::min(packed_cache_path_.size(), runtime::kMaxOptionValueLength - 1);
    memcpy(arr.data(), packed_cache_path_.data(), len);
    option.value = arr;
  } else if (strcmp(option.key, workspace_size_option_key) == 0) {
    const size_t total = workspace_manager_.total_workspace_size();
    // Saturate rather than narrow. OptionValue has no 64-bit alternative and adding one would
    // change the alignment of an INSTALLED type (see the spec). A clamped byte count degrades a
    // memory report; a wrapped negative one corrupts it.
    option.value = static_cast<int>(
        total > static_cast<size_t>(INT_MAX) ? INT_MAX : total);
  }
  return Error::Ok;
}
```

**6c — `set_option`.** Upstream's chain now ends with the `save_weight_cache_on_disk` branch.
Append ours after it, so the function ends:

```cpp
  } else if (strcmp(option.key, save_weight_cache_on_disk_option_key) == 0) {
    auto* val = std::get_if<bool>(&option.value);
    if (!val) {
      ET_LOG(Error, "XNNPACK save_weight_cache_on_disk must be a bool.");
      return Error::InvalidArgument;

  } else if (strcmp(option.key, workspace_size_option_key) == 0) {

    // like it worked. This option is derived state and read-only.
    ET_LOG(Error, "XNNPACK workspace_size_bytes is read-only.");
    return Error::InvalidArgument;
  }
  return Error::Ok;
}
```
